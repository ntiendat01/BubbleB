# AGENTS.md — ContextBubble development rules (mandatory)

## 0. Priority and scope
- Read this file, `docs/PRODUCT_SPEC.md`, `docs/ARCHITECTURE.md`, `docs/SECURITY_PRIVACY.md`, and current milestone in `docs/TASKS.md` **before edits**.
- Follow requirements in priority order: privacy/security > correctness > Android platform compliance > tests > UX > convenience.
- Implement only the active milestone. Do not add cloud sync, screenshot capture, unrestricted autonomous agents, root/ADB automation, telemetry, or unnecessary permissions.
- When requirements conflict, document trade-off in `docs/DECISIONS.md`, prefer non-destructive/least-privilege behavior.

## 1. Hard file size rule
- **No implementation/source code file may exceed 500 physical lines, including blanks/comments** (Kotlin, Java, Gradle scripts, XML UI/config, scripts, JS/TS if introduced, test code).
- Target **<=300 lines per code file**. At >=400 lines proactively split by responsibility. Never bypass rule by minifying, giant one-line expressions, autogenerated code in repo, or placing logic in documentation.
- Files generated by build tools under ignored build directories are excluded; human-authored source/config/tests are not.
- Before milestone completion, run a line-count audit (`find ...` or a script), list violations and resolve them.

## 2. Architecture and code quality
- Kotlin, Jetpack Compose + Material 3, MVVM/UDF, StateFlow, coroutines, Hilt, Room, DataStore, OkHttp.
- `AccessibilityService` is an Android adapter only; no business logic, HTTP operations or persistent state decisions in it.
- Domain must be platform-agnostic where possible; use interfaces at Android/LLM boundaries.
- No blocking network/DB operations on main thread. Bound accessibility traversal and size.
- Structured errors, cancellation propagation, lifecycle cleanup, limited retry. Avoid non-cancellable/global coroutines.
- Never hold or persist `AccessibilityNodeInfo` across asynchronous AI calls; reacquire/validate before any write.
- Use idiomatic Kotlin, meaningful names, small functions, dependency injection, and explicit null/empty/error handling.
- No duplicated constants: centralize limits, result codes, privacy rules and provider endpoints.

## 3. Security / privacy rules — mandatory P0
- All screen access must be **user-initiated**, except minimal app/window state events required to hide/exclude the bubble.
- Before network upload, show a review/consent gate according to `docs/SECURITY_PRIVACY.md`; do not upload before gate.
- Excluded and sensitive apps must fail closed. Never bypass secure/protected views.
- Screen text is ephemeral only; never store in Room, DataStore, disk files, analytics, crash reports or debug logs.
- Do not log API keys, `Authorization` headers, prompts, responses, copied text, OTPs, PII, or raw node hierarchies.
- No silent sending, tapping Send, impersonation, payment, destructive modifications or unrestricted UI automation.
- Use TLS (HTTPS only) for remote provider. Restrict endpoints against accidental insecure hosts; no cleartext exceptions in release.
- API secrets must not be stored in plaintext DataStore. Protect with Android Keystore-backed encryption; design for key invalidation/re-entry. Never commit credentials or examples containing real secrets.
- Build allowlisted actions, not model-defined arbitrary commands. Treat screen content as hostile input.

## 4. Android permissions and UX
- Request accessibility only through Android Settings, with clear disclosure and voluntary enable/disable.
- Do not promise accessibility availability across all apps/ROMs or survival after process death.
- `TYPE_ACCESSIBILITY_OVERLAY` managed by accessible service. No `SYSTEM_ALERT_WINDOW` for MVP.
- Minimal declared permissions (`INTERNET` only plus service binding). No screenshots, mic, contacts or broad storage access.
- Fallback to Android Share for text without Accessibility when feasible.
- On app switch, lock, permission revocation and service disconnect: cancel jobs, clear sensitive context, and hide/detach overlay as applicable.

## 5. Text insertion safety
- No automatic send. **Copy** always available for output.
- Before attempting insertion, require explicit tap, reacquire target, validate package/window/editability/content version and ensure no incompatible state change.
- Default insertion is conservative. `ACTION_SET_TEXT` overwrites full text; do not use for destructive overwrite without explicit confirmation.
- No automatic clipboard fallback without user confirmation where it would replace existing clipboard content; show warning and allow copy only.
- On uncertain cursor/location/stale target, fail safely, never guess.

## 6. LLM integration
- Support provider-agnostic OpenAI-style Chat Completions compatibility **as configured by user**, not assume every provider implements identical streaming/usage/schema.
- No calls just from opening the bubble; send only after user chooses action, reviews payload and confirms.
- Retry only idempotent safe requests under bounded limits; no infinite retries; explicit token/char limits and costs.
- All API error text must be sanitized before display/logging. Cleanly cancel streams on dismiss or context switch.

## 7. Testing and delivery
- For each milestone: implement acceptance criteria, unit tests for pure logic, and documented manual checks.
- At least `./gradlew :app:assembleDebug :app:testDebugUnitTest` when Gradle project/toolchain available. Run lint when configured.
- A passing mock-based test is not equivalent to testing actual OnePlus device.
- For on-device tests, capture **non-sensitive** screenshots/logs only and ask permission if screen sharing is necessary.
- Never declare success without command outputs; if tools/hardware unavailable, mark `NOT_RUN`, reason and reproducible command.
- End each milestone with concise CHANGELOG: files, architecture decisions, tests pass/fail/not-run, risks, next steps.

## 8. Agent working protocol
1. Read requirements and state planned file edits.
2. Implement a single milestone in small coherent commits.
3. Inspect touched files for >500 lines, unsafe logging, hardcoded keys, and unexpected permissions.
4. Build/test; fix issues in milestone scope.
5. Update `docs/TASKS.md` checkboxes only for demonstrated completion. Never fabricate results.
6. Stop and report blockers when Android behaviors vary by device; do not hide scope change.

## 9. Operational boundaries
- No provider keys in repo, ZIP, issues, screenshots or PR.
- App is personal/sideload MVP. Future Play Store release requires separate policy review and compliance work; do not infer approval.
- Documentation is written in Vietnamese; identifiers and code comments can be English.
